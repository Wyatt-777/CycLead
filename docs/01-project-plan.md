# CycleLead AI — 项目规划

## 1. 项目背景

这个项目不是为了展示 AI 技术，而是为了验证一个非常具体的商业问题：

> 能否让 Codex 持续替我完成“寻找潜在自行车行业客户”这一重复工作，并最终提高成交机会？

当前使用者具备：
- 自行车配件相关业务背景；
- 对淘宝、拼多多、闲鱼等电商场景有实际经验；
- 对自行车零部件、组装、维修、经销等客户形态有一定认知；
- 有 Java / Spring Boot 基础；
- 已长期使用 Codex / Claude Code；
- 更适合从轻量 MVP 开始，而不是直接搭建复杂 Agent 平台。

因此，本项目优先追求：

**可用 > 自动化程度 > 技术复杂度。**

---

# 2. 项目目标

## 2.1 核心目标

每天或按需获取一批新的潜在客户，并回答：

1. 这个对象是不是潜在客户？
2. 为什么是？
3. 值不值得联系？
4. 应该优先联系谁？
5. 我从哪里找到他的？
6. 有什么公开联系方式？
7. 是否已经收录过？

## 2.2 MVP 成功标准

第一阶段不以“做出完整系统”为成功。

MVP 成功条件：

- 连续运行 7 天；
- 每天能输出有效候选；
- 人工随机抽查后，合格率达到 60% 以上；
- 每条高分线索能给出明确理由；
- 重复线索比例低于 10%；
- 可以导出 CSV；
- 人工能在 15 分钟左右审阅当天结果；
- 最终至少出现一批“愿意实际联系”的客户。

# 3. 第一阶段目标客户画像

首批优先聚焦：

## A 类：自行车组装 / 改装工作室
典型特征：
- 发布自行车装车视频；
- 提供组装服务；
- 提供升级改装服务；
- 经常展示套件、轮组、传动、刹车、功率计等零件；
- 可能持续采购配件。

优先级：★★★★★

## B 类：自行车门店 / 维修店
典型特征：
- 实体门店；
- 维修、保养、升级；
- 有社交媒体账号；
- 存在持续采购需求。

优先级：★★★★★

## C 类：自行车内容创作者 + 商业服务
典型特征：
- 有装车/维修内容；
- 主页写有装车、维修、咨询、定制等服务；
- 可能既是 KOL，也可能是经销客户。

优先级：★★★★

## D 类：小型品牌 / 经销商
典型特征：
- 自营自行车或配件；
- 网站产品和我方品类存在重合；
- 有批发或渠道采购可能。

优先级：★★★★

## E 类：普通骑行博主
如果只有内容，没有商业行为：
优先级较低。

# 4. 第一阶段数据源

MVP 不追求全网覆盖。

建议顺序：

### P0
- 用户人工提供的种子客户
- Google/Bing 搜索结果
- 商家官网
- 公开社交主页

### P1
- 抖音公开页面（在可合法访问和技术可行范围内）
- 小红书公开页面
- Instagram
- TikTok
- Facebook business page

### P2
- 地图商家
- 行业黄页
- 展会名录
- 经销商目录

第一版只需要实现 1~2 个稳定来源。

# 5. 项目阶段

## Phase 0 — 手工验证

目标：
在写复杂代码前，人工验证客户画像。

任务：
- 准备 20 个“理想客户”样本；
- 准备 20 个“非目标客户”样本；
- 总结二者差异；
- 固化评分规则。

输出：
`fixtures/golden_leads.json`

---

## Phase 1 — MVP

实现：

1. Seed Input
2. Source Collector
3. Parser
4. Normalizer
5. Deduplicator
6. Lead Scorer
7. Evidence Recorder
8. CSV Exporter
9. Run Report

输入示例：

```text
关键词：
自行车组装
公路车装车
bike fitting shop
bike custom build
bike workshop
bicycle repair
```

输出示例：

```text
今日发现：73
完成解析：65
去重后：49
合格客户：18
高优先级：7
```

---

## Phase 2 — Review Dashboard

增加本地页面：

- 今日线索
- 高分线索
- 已联系
- 拒绝
- 忽略
- 备注
- 搜索
- 筛选

状态：

```text
NEW
REVIEWED
CONTACT_LATER
CONTACTED
REPLIED
QUALIFIED
WON
LOST
REJECTED
```

---

## Phase 3 — 半自动研究

对高分客户进行二次研究：

- 官网；
- 产品；
- 所在地区；
- 业务类型；
- 主要品牌；
- 联系方式；
- 采购可能性；
- 推荐切入产品。

生成：

```text
Lead Brief
```

但仍不自动联系。

---

## Phase 4 — Codex Automation

MVP 稳定后再设置：

```text
每天
↓
运行 lead discovery
↓
去重
↓
评分
↓
只保留高价值客户
↓
输出日报
```

# 6. 暂时不做

第一阶段明确不做：

- 自动群发；
- 自动私信；
- 自动 WhatsApp；
- 自动邮件；
- CRM 大系统；
- RAG；
- 多 Agent 编排；
- 云服务器；
- SaaS；
- 手机 App；
- 复杂权限系统；
- AI 自动成交。

这些都属于“验证以后”的事情。

---

# 7. 商业验证指标

系统每天至少记录：

```text
discovered_count
qualified_count
high_score_count
duplicate_count
manual_true_positive_count
manual_false_positive_count
contacted_count
reply_count
converted_count
```

核心 KPI：

## Precision
人工认为真正值得开发的线索 / AI 推荐线索

初期目标：

```text
>= 60%
```

后续目标：

```text
>= 80%
```

## Lead-to-contact
推荐线索中最终愿意人工联系的比例。

## Reply Rate
进入真实开发阶段后再统计。

## Conversion Rate
最后才是最重要的商业指标。

---

# 8. 最重要的产品原则

项目每增加一个功能，都必须回答：

> 这个功能会不会提高“发现真实潜在客户”的概率？

如果不会，就暂时不开发。
